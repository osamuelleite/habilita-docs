|---|---|

## 1. Contexto

O Caderno prevê, por gate:

| Gate | Exigência de pipeline e deploy |
|---|---|
| CP1 · 18/10 | CI com lint e build a cada PR; proteção da `main` |
| CP3 · 15/11 | Firebase Hosting, Cloud Run, preview em PR, produção após merge, rewrite `/api`, Workload Identity Federation (sem chave JSON permanente), imagens com SHA, retenção das últimas 5, sem `latest` em produção |
| CP4 · 29/11 | Trilhas paralelas; lint bloqueia build; build bloqueia testes; falha bloqueia deploy; varredura de segredos, dependências e imagens; rollback ensaiado |

Até a Semana 4 tudo roda localmente. A documentação já tem pipeline próprio (`.github/workflows/docs.yml`, ADR 0004).

## 2. Opções consideradas

| Opção | Prós | Contras |
|---|---|---|
| Cloud Functions para a API | Escala a zero | Ambiente local (contêiner) divergiria do de produção |
| **Cloud Run para a API** | Mesmo contêiner do Compose; escala a zero | Cold start |
| Frontend no Cloud Run | Uma plataforma só | Hosting já oferece CDN e canais de preview prontos |
| Chave JSON de conta de serviço no GitHub | Simples de configurar | Credencial permanente; proibido pelo Caderno |
| **Workload Identity Federation** | Sem segredo permanente | Configuração inicial trabalhosa |

## 3. Decisão

- **Frontend:** SPA no **Firebase Hosting**, com rewrite de `/api/**` para o Cloud Run (mesma origem, sem CORS em produção).
- **API:** contêiner no **Cloud Run**, `min-instances=0`, `max-instances` baixo (proposta: 3), região `southamerica-east1` (São Paulo).
- **Agendador:** Cloud Scheduler na mesma região (ADR 0007).
- **Pipeline de aplicação (GitHub Actions), separado do pipeline de docs:**
  - Todo PR: lint → build → testes, cada etapa bloqueando a próxima; a partir da S6, deploy de preview.
  - Merge na `main`: imagem com tag = SHA do commit, push para o Artifact Registry, deploy em produção, smoke test.
  - Autenticação no GCP por **Workload Identity Federation**; nenhuma chave JSON no repositório nem nos secrets.
  - Rollback: redirecionar tráfego para a revisão anterior do Cloud Run.
- **Pipeline de docs:** mantido como definido no ADR 0004 (`mkdocs build --strict` em todo PR; GitHub Pages após merge).

## 4. Consequências

**Positivas**

- Ambiente local fiel ao de produção; custo próximo de zero sem uso.
- Preview por PR facilita revisão; rollback em segundos.

**Negativas / custos**

- Dois workflows (app e docs) para manter.
- WIF exige configuração inicial cuidadosa.

**Obrigatório:** nenhum recurso novo no GCP sem ADR ou aprovação do Tech Lead (DoD); conferir disponibilidade e preço dos serviços na região antes de criar.

## 5. Riscos e mitigação

| Risco | Mitigação |
|---|---|
| Deploy quebrado na véspera do gate | Smoke test pós-deploy e rollback ensaiado no CP4 |
| Preview de PR acumulando custo | Expiração dos canais de preview e limpeza de revisões antigas ([FinOps](../../finops/index.md)) |
| Imagens antigas ocupando armazenamento | Retenção das últimas 5 no Artifact Registry |

## 6. Validação da decisão

- [ ] CI com lint e build verdes em todo PR até 18/10.
- [ ] Proteção da `main` ativa (PR obrigatório, 1 aprovação, CI obrigatório).
- [ ] Checklist do CP3: preview em PR, produção após merge, rewrite `/api`, WIF, imagens com SHA.
- [ ] Rollback ensaiado e registrado em [Operação](../../operacao/index.md) no CP4.
